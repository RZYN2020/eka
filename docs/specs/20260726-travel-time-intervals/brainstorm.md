# 旅行时间区间模型 Brainstorm

## Background

当前旅行数据同时承担页面分组、地点时间和路线出发地三种职责。路线生成器依赖
`主基地 → 旅行 → 次主基地` 的静态嵌套，并默认每次旅行都返回父基地，因此无法自然表达：

- 人生阶段末尾已经离开原主基地，但尚未进入下一个主基地；
- 次主基地期间的短程旅行应该返回次主基地；
- 最后一个持续驻留地点与人生阶段同时结束，应从该地点直接进入下一阶段。

此前为 2020 年“兰州 → 庆阳 → 南京”的迁移加入 `oneWay` 特例，只修复了一个症状，
没有建立统一的时间语义。

## Goals & End State

- 旅行数据仍然只维护一份。
- 每个主基地、次主基地和普通旅行地点都有机器可读的起止时间。
- 路线由时间区间、地点类型和基地层级统一派生。
- 没有旅行或次主基地覆盖时，人默认位于当前人生阶段的主基地。
- 次主基地期间的短程旅行默认返回次主基地。
- 人生阶段结束时，从最后实际停留的地点前往下一个主基地。
- 月份或季节级历史信息保留原精度，不伪造具体日期。
- 删除 `oneWay` 等针对单条经历的路线特例。
- 保持现有地图视觉、动画播放、手动步进和时间轴拖动行为。

## Key Decisions

| Decision | Choice | Rationale |
| --- | --- | --- |
| 主基地语义 | 人生阶段容器 | 主基地定义阶段归属，不要求人在整个区间内始终身处该城市 |
| 时间模型 | 每个地点具有 `start` 和 `end`，当前持续基地允许 `end: null` | 起止区间同时支持排序、驻留和阶段切换 |
| 普通旅行 | 暂视为短暂访问；未知持续时间时令 `end = start` | 不虚构未知日期，且保持“旅行后返回基地”的既有事实 |
| 当前基地 | 使用主基地、次主基地组成的基地栈 | 内层次主基地在有效区间内优先于外层主基地 |
| 短程回程 | 返回当时基地栈顶部 | 次主基地期间不会错误返回主基地 |
| 次主基地结束 | 早于父基地结束则返回父基地 | 恢复该人生阶段的默认所在地 |
| 阶段末尾承接 | 最后一个持续驻留地点与父阶段同时结束时，不生成返回父基地，直接进入下一主基地 | 自然表达毕业、搬家和基地切换，无需单程布尔特例 |
| 同期事件排序 | 使用部分 ISO 时间后再按 `sequence` 排序；结束边界使用 `endSequence` | 保留月份、季节级精度，同时表达已知先后 |
| 数据检查 | 子区间必须包含在父区间内；区间冲突、缺失边界和无效顺序在验证时失败 | 防止地图静默生成错误路线 |
| 连续行程 | 相邻访问通过相同 `journeyId` 显式分组 | 支持真实多城市路线，同时不根据日期自动猜测或改变普通访问的回程语义 |

## Out of Scope

- 不补造用户没有提供的具体日、时刻或旅行时长。
- 不根据地图距离推测交通方式或现实道路。
- 不重新设计地图视觉、配色、头像、侧栏或时间轴控件。
- 不在本功能中处理 GitHub 与 Cloudflare Pages 部署。
- 不把普通旅行自动合并为多城市连续旅程；默认仍在两次普通旅行之间返回当前基地。

## Risks & Mitigations

- Risk: 月份或季节级日期不足以表达同一时期的真实顺序。
  - Mitigation: 保留 `sequence`，显示标签与机器排序字段分离。
- Risk: 主基地作为人生阶段容器，可能被误读为全程实际居住。
  - Mitigation: 在数据命名和设计中明确区分 `phase` 与实际驻留地点。
- Risk: 旧数据缺少 `end`，一次性迁移可能错误猜测旅行时长。
  - Mitigation: 普通旅行默认 `end = start`；仅对用户已经确认的持续驻留填写跨期区间。
- Risk: 递归基地栈可能重复生成返回节点或产生时间倒序。
  - Mitigation: 为普通回程、次主基地回程、阶段末尾承接和嵌套旅行分别建立数据级回归测试。
- Risk: 新路线节点数量变化会使浏览器测试中的固定数量失效。
  - Mitigation: 测试关键语义节点和相邻路线，固定数量只作为辅助检查。
